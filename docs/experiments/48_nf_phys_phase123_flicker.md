### 1.2 그 편중이 VIPL 을 해치는가 — 기존 결과로 본 간접 검정

가설 메커니즘: "54–78 bpm 의 균일 밝기 변조를 무시하도록 배운 모델이, 같은 대역의 참 맥파(특히 저해상 휴대폰 영상)를 함께 억제한다". 그렇다면 VIPL 오차가 **54–78 bpm 구간에서 선택적으로** 나빠야 한다.

- 플리커 사본을 사실상 버린 GroupDRO 의 이득은 전 구간(−1.3/−0.8/−1.6/−2.4/−2.3)에 고르고 고심박에서 더 크다 → 그 이득은 MCD 도메인 적합이지 플리커 학습 제거 효과가 아니다.
- 공정 출발점에서 플리커 사본 44 를 **더하면**(U2→U3) 플리커 띠를 포함한 전 구간이 좋아진다(54–66 −1.4, 66–78 −1.6, 전체 −1.98).
- MCD ×4 가중 셀(체인 56)은 플리커 강건성(RTN 0.9/1.8)을 유지한 채 VIPL 8.27 로 개선 → 플리커 불변성과 VIPL 은 직접 상충하지 않는다.

판단 ②: 기존 증거는 "플리커 편중이 VIPL 을 해친다" 를 지지하지 않는다. VIPL 격차는 고심박(≥78 bpm)·운동 후 구간의 현상이다(42 문서).

**정정(10-28 02:10, 직접 검정 결과 반영)**: 위 간접 증거는 공개 FactorizePhys 와의 비교였지 '같은 코퍼스에서 플리커만 뺀 모델' 과의 비교가 아니었다. 체인 65(§5.2)의 짝 풀 직접 검정은 플리커 사본 제거 시 VIPL 이 0.62 좋아지고 그 이득이 **플리커 띠(54–66 bpm −1.25, 66–78 −0.53)와 웹캠 소스(−1.70)에 집중**됨을 보였다 — 사용자의 우려 방향이다(시드 1, 공식 모델 시드 분산 8.08–9.65 안이라 시드 3개로 확인 중, 체인 65b). 판단 ②는 "근거 없음" 에서 "단일 시드 지지, 대가는 플리커 강건성·근적외선·MMPD 움직임" 으로 바꾼다.

47 문서 설계와의 차이(정직 기록):
- **입력**: FactorizePhys 트렁크는 내부에서 `torch.diff` 후 InstanceNorm 을 쓴다(원시 프레임을 받지만 차분 입력). 47 §2 의 "원시 표준화 입력" 원칙은 "FactorizePhys 트렁크 레시피 그대로" 로 구현했고 무차분 변형은 스위치만 둔다(체인 57 의 원시 입력 이득은 PhysFormer 에서 관측된 것).
- **스펙트럼 헤드 → 스펙트럼 손실**: 별도 HR 헤드는 정본 읽기(파형 periodogram)와 다른 읽기 계열을 만들므로, 출력 파형의 스펙트럼에 손실을 거는 형태로 바꿨다. 읽기 프로토콜은 FactorizePhys 와 동일(Standardized 라벨, cumsum 없음).
- **슬롯 정체성**: NMF 기저는 순서가 없으므로 초기값(맥파 = 상수, 교란 = 클립 자신의 전역 trace)으로 역할을 고정하고 감독으로 유지한다(47 §5 의 "고정 trace 변형" 과 "학습 기저" 의 중간).
- FSAM 행렬 배치: 원 코드의 `view` 는 permute 가 없어 행이 (채널, 8프레임 블록) 이 되어 있었다. NF-FSAM 은 행 = 시간으로 고친다(시간 trace 감독의 전제). 공개 체크포인트의 1×1 conv 는 그대로 적재된다(17 키 중 16 적재, `bias1` 은 원 코드 특성상 저장되지 않는 값).

검증: CPU 단위 검사(순전파 0.1 s·역전파 0.2 s, 손실 정합: 순수 맥파 spec 0.55 vs 오라벨 5.13, 반감 0.008 vs 0.996) · GPU 스모크(8클립 풀: 청정 3·DN 3·플리커 사본 2, 1 epoch: `gate=42/70`(≈5/8 클립 ✓) `ngt_hit=18` 손실 유한, UBFC held-out 청크 MAE 1.10) · 평가 경로(PURE held-out 0.75, 공개 FactorizePhys 0.74 와 동급 → 웜스타트 보존) · 집계기(`label_type` Standardized, cumsum 없음).
