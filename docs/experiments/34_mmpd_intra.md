# 34. MMPD 피험자 배타 5-fold 인트라 실험 설계 (체인 52, 사전 등록, 2026-10-17)

사용자 지시(10-17 /goal): "MMPD 인트라 5-fold 체인 설계서로 옮겨주고 제로샷뿐만 아니라 MMPD, VIPL 데이터셋 각각에서 기존 방법 대비 정확도 향상이라는 근거도 확인". 근거 현황표는 33 문서 §5, 본 문서는 MMPD in-domain 체인의 설계.

## 1. 배경 — 이미 있는 것과 빈 것

- **체인 28(16 문서 §16-16) MMPD 3-fold**(fold 1~11 / 12~22 / 23~33, 학습 = 공식 코퍼스 203 + 나머지 두 fold 의 짝수 트라이얼 220 클립, 단일 시드): 33명 660편 합산 **9.11** — 공식 모델(MMPD 미포함) 10.21 대비 −1.10(p=.0006), POS 12.17 대비 −3.06, 공식 PhysFormer/RhythmFormer UBFC 가중치 14.68/14.94 대비 −5.6/−5.8. **그러나 이득은 정지 조건에 집중**(정지 5.41 vs 공식 모델 8.03, p<.0001)이고 **움직임 합산은 11.57 vs 11.66(ns), 보행 20.94 vs 18.43(악화 방향 ns)** — in-domain 실 데이터는 움직임을 못 고친다.
- 반대로 **하이브리드 분해(MMPD 1~6 포함, 5시드)** 는 움직임 10.60·보행 18.12 를 고치지만 정지는 8.33 으로 in-domain 셀(5.41)에 못 미친다. → "데이터는 정지를, 분해 목적함수는 움직임을 고친다"는 상보 구조가 보이며, **둘을 합친 셀(in-domain + 하이브리드)은 아직 없다.**
- **기존 방법의 in-domain 기준선이 없다**: 문헌 인트라 PhysFormer 11.99(RhythmFormer 논문 재구현, mini-MMPD, 순차 7:1:2)만 있고, 우리 프로토콜로 MMPD 만 학습한 PhysFormer 셀은 없다. "기존 방법 대비 in-domain 향상" 주장에는 이 셀이 필수.
- 기준선 읽기 정정(33 §5): 표준화 라벨 모델(FactorizePhys·RhythmFormer)의 읽기를 툴박스 규칙으로 고치면 FactorizePhys UBFC 가중치의 MMPD held-out zero-shot 이 **9.79** 로, 우리 하이브리드 9.69 와 동등하다. 따라서 MMPD 에서 "기존 방법 대비 향상"은 in-domain 셀로만 보일 수 있다.

## 3. 설계

- **분할**: 33명을 피부톤(3~6) 층화 round-robin(시드 0)으로 5 fold(7/7/7/6/6) — `_workspace/data/physformer/mmpd_folds.json`(생성 후 불변). 학습 = 나머지 4 fold 피험자의 **전 20 트라이얼**(체인 28 의 짝수 절반과 달리 전부), 평가 = held-out fold 피험자의 전 20 트라이얼 → 5 fold 합산 660편, 각 영상은 자기 held-out 모델로만(누수 assert).
- **셀(fold k=1..5, 시드 100)**: `MF{k}_BASE_L` = UBFC 체크포인트 미세조정 + MMPD 학습 fold 만(기존 방법 PhysFormer 의 in-domain 기준선, 우리 레시피: 10 ep·lr 5e-5·batch 4·cumsum 라벨) / `MF{k}_TW_L` = + 공식 코퍼스 203 / `MF{k}_HYB_L` = + HYB4 풀 + 하이브리드 손실(31 문서와 같은 HYB 환경). 15 run.
- **문헌 분할 참고(Phase 2)**: `ML_BASE_L`·`ML_HYB_L`(학습 1~23, 테스트 27~33, 검증 24~26 미사용) 2 run — RhythmFormer 논문 표(PhysFormer 11.99·RhythmFormer 3.07·PhysFormer++ 4.88)와 같은 줄에 "프로토콜 상이" 로 둔다.
- **데이터 경로**: 7~33 홀수 트라이얼 270 클립 추가 변환(`convert_mmpd_odd.py`) → 660 클립 풀 `COTRAIN_MMPD_ALL` → uint8 스트리밍 캐시 `cache/mmpd_all_u8`(`nirp_pool_stream.py`, 메모리 <1 GB/워커) → 속성 사전 `mmpd_trials.json` → 목록 `mmpd_{train,test}{k}[_POOL].csv`, `mmpd_lit_*.csv`(`mmpd_filelist.py`). 학습·테스트는 VIPL-HR 로더 + csv(`vipl_yaml.py train … --test_csv`), 집계 `agg_mmpd_cv2.py`(툴박스 정본 읽기, 라벨 유형별), 판정 `mmpd_judge.py`.
- **환경 불변**: 체인 50 의 증강·검증 선택은 쓰지 않는다(체인 28·46 과 같은 기본 레시피로 비교 가능성 유지). 증강이 체인 50 에서 채택되면 `MF{k}_HYBA_L` 추가는 Phase 3(사용자 결정).
- **평가**: 정본 프로토콜 영상 HR; 층 = 정지/회전/대화/보행/움직임 합산, 피부톤 5·6, held-out 7~33 부분집합(zero-shot 모델과의 비교용). 기준: POS·CHROM·공식 UBFC 가중치 3종(정정 읽기), zero-shot 공식 모델 `CoTAF_TW_L`, 하이브리드 `CoTAM_HYB4_L`(MMPD 1~6 학습 → 7~33 만), 체인 28 3-fold.

## 4. 판정 규칙

- 1차 가족 3건(H-M1 전체, H-M2 움직임 합산, H-M3 vs POS 움직임 합산) Holm 보정; 나머지는 원 p 와 효과 크기 보고.
- 시드: 단일 시드 1차. H-M2 가 유의하면 시드 200·300(TW·HYB × 5 fold = 20 run ≈ 40 h)은 **사용자 결정**(Phase 3). 비유의면 추가 없음.
- 붕괴 점검: 어느 셀이든 held-out r<.3 이면 학습 사고로 보고 원인(라벨·캐시) 확인 후 재실행.
