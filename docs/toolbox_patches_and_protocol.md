# rPPG-Toolbox patches and protocol notes

Extracted from the project's operational guide. Every behaviour is gated by an environment variable and defaults to upstream behaviour unless noted. Internal cell names (for example `NF_NSP2_L` = SpecPhys, the final model) are the identifiers used in the scripts and in `docs/experiments/`.

## Local patches to rPPG-Toolbox (must survive any re-clone)

`git -C repos/rPPG-Toolbox status` lists the modified files (16 patched + new `dataset/data_loader/VIPLHRLoader.py`). Behaviour is gated by env vars, all defaulting to upstream behaviour except where noted:

| Var | Effect |
|---|---|
| `RPPG_HR_LABEL=cumsum` | Training HR label from integrated+detrended+bandpassed PPG instead of Welch-on-diff (which labels 2f in 10–52% of windows). **Always set for training.** Models trained with it carry the `_L` suffix; never compare `_L` models against legacy baselines. |
| `RPPG_SEED` | Random seed (default 100). |
| `RPPG_MP_QUOTA` | Preprocessing worker count (default 8; use 4–6 on this shared box). |
| `RPPG_CACHE_U8=1` | Store crop/resized **uint8** frames (+ per-video `_u8scale.npy`) instead of float32 DiffNormalized chunks and rebuild DiffNormalized in `__getitem__` (4× smaller cache, numerically identical; chunks carry one overlap frame). For `DATA_TYPE: [DiffNormalized]`; with `[Standardized]` the loader instead standardises each chunk by the per-video `{name}_u8stats.npy` sidecar (`scripts/vipl_u8_stats.py`; `vipl_yaml.py --std`, literature-recipe variant cell). Required for every VIPL run and for pools mixed with VIPL. |
| `RPPG_CACHE_MIN_FREE_GB` | Hard disk guard in `BaseLoader` (default 40 GB) — aborts preprocessing. `chain_lib.sh::wait_disk` (`VF_DISK_MIN_GB`, 60 GB) is the softer first barrier. |
| `SINC_PRIOR`, `SINC_DN_ONLY`, `SINC_ADAPTIVE`, `SINC_W_*` | SiNC-style frequency prior loss (off by default). |
| `RPPG_NOISE_HEAD`, `RPPG_HYBRID`, `HYB_W_*`, `HYB_NOISE_GT_DIR`, `RPPG_CONF_DUMP` | Dual-render noise head / hybrid loss / confidence head (chains 39–43). |
| `PF_HARM_*` | Harmonic penalty loss (see `scripts/patches/physformer_harm_loss.patch`). |
| `RPPG_HR_LABEL_FILE=1` | Training HR label from a per-frame sidecar `{cache}/{name}_hr.npy` (chunk mean) when present, else the usual label. VIPL sidecars hold the device HR (`gt_HR.csv`, literature GT; `scripts/vipl_hr_sidecar.py`). The trainer prints `HRFILE sidecar hits=a/b` at epoch 0 batch 200 — a chain must fail when hits=0 (the toolbox already appends `EXP_DATA_NAME` to `CACHED_PATH`; appending it again silently disabled the label on 2026-10-14). |
| `PF_LOSS_A` | Weight of the Neg-Pearson waveform term in the PhysFormer loss (default 1.0; the official PhysFormer code uses 0.1 — used by the literature-recipe cell). |
| `RPPG_PEARSON_SKIP_RE` | Regex on the chunk name (`batch[2]`, e.g. `p45_v1_s2`); matching samples are dropped from the Neg-Pearson waveform loss and supervised by the frequency (HR) losses only. **Set to `'^p[0-9]+_v[0-9]'` for every VIPL training run**: VIPL wave labels are not phase-locked to the video (lag-0 correlation ≈ 0), so the waveform loss only drives subject memorisation (fold-1 in-sample r .76 vs held-out r .01). |
| `RPPG_TAUG=1`, `RPPG_TAUG_P` (0.5), `RPPG_TAUG_HR_SPLIT` (88) | Temporal speed augmentation in the uint8-cache train loader (patch #30, `_workspace/32_*.md`; **patch 44** (`_workspace/60_*.md`, chains 81–82) extends it to `Standardized`/`Raw` inputs — RhythmFormer, FactorizePhys — by resampling the frames before the input conversion, applies the Standardized-label reconstruction of patch 40a to augmented labels, and makes the RhythmFormer/PhysMamba/FactorizePhys trainers print `TAUG stats epoch k: {...}` too): per sample with prob. p, chunk HR > split → half speed (frame interpolation, HR÷2), else double speed (joins the next chunk, frame skipping, HR×2; skipped when no next chunk). Labels resampled exactly, DiffNormalized std preserved, tag `|x2`/`|x0.5`/`|skip` appended to the chunk name and stripped by the PhysFormer trainer (which scales the sidecar HR label). Trainer prints `TAUG stats epoch k: {...}` — a chain must fail when `x2` is absent. |
| `RPPG_VALID_METRIC=mae` | PhysFormer validation returns chunk-HR MAE instead of RMSE for best-epoch selection (`TEST.USE_LAST_EPOCH: False`); with `RPPG_HR_LABEL_FILE=1` the validation label HR comes from the `{name}_hr.npy` sidecar (patch #31). `scripts/vipl_filelist.py valid K` / `train K --xv` build the subject-exclusive VIPL validation split (`vipl_valid_subjects.json`, fixed), `scripts/vipl_yaml.py --valid_csv` wires it in. |
| `RPPG_NUM_WORKERS` (16) | DataLoader worker count in `main.py` (train/valid/test). Upstream default 16 costs ≈0.9 GB RSS per worker, so one evaluation run takes ≈15 GB; `chain_lib.sh` exports 6 (override per chain: `RPPG_NUM_WORKERS=4 bash scripts/run_chainNN.sh`). `RPPG_MP_QUOTA` is likewise overridable. Never run more than two toolbox processes plus one preprocessing job at once on this 46 GB box. |
| `RPPG_SKIP_NAN_LOSS` (1) | PhysFormer trainer skips a batch whose total loss is non-finite instead of back-propagating it (patch 33; a single near-constant label chunk otherwise turns every weight to NaN and the run predicts a constant HR — MMPD cell, 2026-10-17). Prints `NAN_SKIPPED epoch k: n batches`. Training file lists must still drop label chunks with std ≤ 0.1 (`vipl_filelist.py` / `mmpd_filelist.py` filters). |

## Non-negotiable protocol rules

- **Lossless only** for injected video (PNG frames or FFV1 `vid.avi`). Any lossy codec destroys the <1% modulation; compression variants are deliberate ablations with GT md5-checked provenance.
- **Synthetic pulse mask leaks into backgrounds (66 §6.3, §8).** `build_synth_dataset.py`'s YCrCb `stable_skin_mask` injects the pulse into warm-coloured backgrounds: about half of the generated-face training clips (38 of the original 80; identities sfhq_01/06 worst) and 3 of 4 held-out stress identities. Any background- or side-band-referenced method behaves differently on these clips than on real video. New synthetic clips should set `skin_mask_parser: true` (YCrCb ∧ SegFormer skin); the `_CLEAN` stress sets and cache `sepevalc_u8` are the corrected test versions. Waveform correlation on synthetic clips must be lag-corrected (`scripts/sepx_lag.py`): every model lags the injected PPG by 3–4 frames. Retraining the final model on the 90 regenerated clips (`cotrain_allf_hyb4c_u8_pool.csv`, cell `NF_NSP2C_L`, 67 §5) changed no primary metric and failed the MMPD ≥110 guard, so the reported model was kept; the synthetic clips' MMPD cost persists without the leak (+0.75, Holm .004) and their VIPL-HR gain becomes significant (−0.32, Holm .001).
- **Synthetic clips and heart-rate range (68 §2–§6).** In the real pool identity explains 65 % of chunk-HR variance (synthetic 2 %). On the controlled sweep `HRSWEEP40`/`HRSWEEP40LO` (four held-out identities × 45–180 bpm, scene fixed; `scripts/make_hrsweep_config.py`, eval `scripts/run_set_eval.sh`, metrics `scripts/hrsweep_metrics.py` with `HRSWEEP_SET=LO`) the final recipe without synthetic clips misreads weak-pulse low heart rates (12.5 vs 1.3 bpm); tying the synthetic HRs to identity (`NF_NSP2K_L`) keeps the benefit, so the active ingredient is HR-range coverage, not identity decoupling; within-clip HR ramps (generator option `bpm_curve`) and same-scene pairs add nothing. Within-subject tracking on real video: `scripts/idhr_within_subject.py`.
- **Contribution evidence (69 §2–§4, chain 128).** Controlled sweep against existing methods and final-model seeds: `scripts/run_chain128_contrib.sh` (eval-only jobs reuse each baseline's `yaml_VIPL/ev_*_VIPL.yaml` with the sweep csv; RhythmFormer needs `_u8stats.npy` from `scripts/u8_stats_any.py CACHE 1`); `scripts/hrsweep_metrics.py` now integrates difference-normalised outputs per chunk before the FFT (Standardized-label outputs unchanged) and writes a band-pass sensitivity with `HRSWEEP_BP=1` (`*_bp.json`); judge `scripts/contrib_judge.py` (A sweep, B within-subject slope, C halved/doubled share, D scarce real data), figure `scripts/contrib_figs.py`, supplement tables `scripts/contrib_supp.py`. The weak-pulse sweep advantage (1.18 vs. 11–38 bpm) comes from the generated-face clips and is in-domain for the generator; with a quarter of the real subjects (`scripts/make_scarce_pools.py`, cells `NF_NSP2{Q,QN,SO}_L`) the synthetic clips lowered no real-video error, and fine-tuning on them alone worsened VIPL-HR (6.88 → 7.85).
- **Canonical HR protocol**: real axes = toolbox pipeline (cumsum → detrend λ=100 → Butterworth 0.6–3.3 Hz → periodogram); synthetic axes = 8× zero-padded FFT 0.7–4.0 Hz. The cumsum step applies only to DiffNormalized-label models (toolbox `diff_flag`); for Standardized/Raw-label models (RhythmFormer, FactorizePhys, …) the aggregators skip it, selected per saved pickle `label_type` by `agg_model2.hr_for` (fixed 2026-10-17; `RPPG_AGG_FORCE_CUMSUM=1` reproduces the legacy numbers kept in `results/legacy_readout/`). Doubling |ratio−2|<0.2, halving |ratio−0.5|<0.1. Never mix protocol families in one table; the chunk-level metrics the toolbox prints are not paper numbers.
- **Split invariants**: DLCN and MR-NIRP are pure zero-shot (never in any training pool). MCD eval identities 1–20 vs train 21–44, PURE held-out subjects 07–10, UBFC held-out 42–49, MMPD train subjects 1–6 only. In-domain and zero-shot results are always labelled separately.
- **Honest reporting**: adverse results are reported as-is (see the many "채택 불가" rows in the change log). Every number in a manuscript must trace to an `agg_*.json` or `_workspace/16_*.md`.
- Paired comparisons use ≥3 seeds (5 for headline claims) and Wilcoxon signed-rank per video.
- Do not use bare code-style labels (C1, T2L, HYB4) alone in prose or summaries; pair them with a descriptive name.
