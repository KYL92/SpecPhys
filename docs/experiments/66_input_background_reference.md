# 66. 입력 단계 배경 기준 보정 — 물리 규칙 게이트 (체인 125, 사전 등록 11-07)

## 1. 왜 하는가
사용자 지시(11-07): "3. 다른 설계로 다시 시도합니다. 예를 들어 입력 단계에서 피부 화소와 배경을 직접 비교하는 방식입니다 … 진행해줘요."

배경은 다음과 같다.
- 65 §6: 특징 수준의 학습된 빼기와 이중 렌더 정답으로는 같은 주파수 잡음을 가른 근거가 없었다. 투영 층은 참조와 같은 주파수의 성분을 통째로 지운다. 그래서 전역 플리커가 심박 4 bpm 안이면 출력이 심박을 잃는다(심박 판독 0~42 %).
- 이 경우의 단서는 입력 화소에 있다. 배경에는 맥박이 없고 조명 변화만 있다. 피부 화소를 배경 밝기로 나누면 공유 조명 변화가 주파수와 상관없이 지워진다.
- **같은 생각을 이미 시험했다(61 §6~§7, 패치 51·51b).** 배경으로 무조건 나누는 방식은 실제 영상에서 해로웠다(MMPD 보행 역방향 유의, VIPL·MMPD 가드 위반). 원인은 실제 배경이 어둡고 압축 잡음이 커서 배경 변동이 피부 변동만큼 크고, 피부–배경 고역 상관이 약하다는 것이었다(중앙값 0.15~0.27). 청크마다 회귀 계수를 맞추는 방식(51b)은 고심박을 +3.9~5.0 bpm 악화시켰다.

이번 설계는 세 가지가 다르다.
1. **나눌지 말지를 청크·채널마다 정한다.** 배경이 피부와 조명 변화를 실제로 공유한다고 보일 때만 그 채널을 배경으로 나눈다(§2.2). 패치 51 은 모든 청크를 나눴다.
2. **화소 자신의 시간 신호에 보정량을 맞추지 않는다.** 나눌 때는 a = 1 로 정확히 나눈다. 51b 처럼 청크마다 회귀 계수를 맞춰 맥박을 흡수하지 않는다.
3. **보정한 입력에서 잡음 참조를 다시 계산한다.** 투영 층의 측면 띠 참조에서도 공유 조명 변화가 지워지므로, 투영이 심박 주파수를 통째로 지우지 않는다.

처음에는 화소별 보정량을 작은 망이 배우게 했다(§2.1). 그러나 공학 점검에서 게이트가 열리지 않아, 학습 없는 물리 규칙 게이트로 바꿨다. 이 결정은 학습 손실과 입력 통계만 보고 내렸고, 시험 오차는 보지 않았다.

## 2. 구현 (패치 57, 점검 완료)
- **로더 (`RPPG_PARSE_CH=1`):** 피부 가중에 쓰는 부위 분할 사이드카(피부·배경·얼굴 내 비피부 확률)를 프레임 크기로 늘려, 시간에 불변인 채널 3개로 입력에 덧붙인다(6채널). 사이드카가 없으면 0 채널이다. 학습 풀(u8)과 평가 축(float Raw) 모두에서 확인했다: 6채널, 사이드카와 최대 차 0(`scripts/bgref_smoke.py`).
- **모델 (`NF_BGREF=1`, `BgRef`):** 안정 배경(배경 확률 ≥ 0.875, 크롭의 ≥ 3 %)의 채널별 로그 밝기 변화 ρ_c(t) 를 구하고, x̃ = x·exp(−a_c(x)·ρ_c(t)) 로 보정한다. a = 1 이면 패치 51 의 나눗셈, a = 0 이면 그대로다. 보정한 프레임으로 트렁크 입력, 전역 trace, 투영 참조를 모두 다시 계산한다. 학습 모드(`NF_BGREF_MODE=learn`, 275 파라미터, 0 초기화)와 게이트 모드(`NF_BGREF_MODE=gate`, §2.2)가 있다. 학습 모드는 시작 시 출력이 현재 최종 모델과 같다(CPU 확인, 최대 차 0).
- **CPU 물리 점검:** 배경과 피부에 같은 1.2 Hz 플리커를 걸고 피부에 같은 주파수의 맥박을 넣은 합성 입력에서 a = 1 로 고정하면, 배경 변동이 사라지고(표준편차 2.56 → 0.00002) 보정한 피부 신호가 맥박과 상관 1.0 이 된다(보정 전 0.65).
- **트레이너:** `BGREF stats epoch k: ok= a_skin= a_bg= on(a_skin>0.3)= syn_a_skin= real_a_skin=` 를 찍는다. syn 은 플리커가 있는 이중 렌더 클립(피험자 261~308, 2001~2048)이다. 게이트 모드에서 a_skin 은 나눈 채널의 비율이다. 체인은 이 줄과 `ok>0`·`on>0`, 학습·평가 로그의 `[bgref] module active: mode=gate`·`[parse-ch] active` 를 확인한다(평가는 strict=False 로 체크포인트를 읽는다). 게이트 학습률 배수 `NF_BGREF_LRX` 는 학습 모드 점검에만 썼다.
- 손실은 바꾸지 않았다. 이중 렌더 정답은 쓰지 않는다(64·65 에서 효과 없음).

### 2.1 공학 점검: 학습 모드 게이트는 열리지 않았다(판정에 쓰지 않음)
시드 1, 학습 손실과 게이트 통계만 봤고 시험 출력은 보지 않고 지웠다.

| 점검 | 피부 화소 평균 보정량 a | a > 0.3 인 청크 | 합성 플리커 클립 / 실제 클립 |
|---|---|---|---|
| 1에폭, 학습률 배수 1 | 0.002 | 0 | 0.003 / 0.002 |
| 2에폭, 학습률 배수 10 | 0.021 | 0 | 0.021 / 0.021 |
| 2에폭, 학습률 배수 30 | 0.042 | 0 | 0.040 / 0.043 |

게이트는 거의 열리지 않았고 합성 플리커 클립과 실제 클립을 가리지 못했다. 심박 스펙트럼 손실은 심박 대역 안의 전력이 맥박인지 같은 주파수의 플리커인지 구별하지 못하므로, 출력 손실이 게이트를 선택적으로 여는 신호가 약하다(해석). 이대로면 기준과 거의 같은 모델이 나와 정보가 적다고 판단해 §2.2 로 바꿨다.

### 2.2 물리 규칙 게이트 (`NF_BGREF_MODE=gate`, 학습 없음, 결과 전 확정)
청크·채널마다 다음을 모두 만족하면 그 채널을 배경으로 정확히 나눈다(a = 1, 모든 화소). 아니면 그대로 둔다(a = 0).
- 피부–배경 1 s 고역 로그 밝기 상관 κ_c ≥ 0.6. 61 §6 의 실제 데이터 중앙값(0.15~0.30)보다 높게 잡았다.
- 배경/피부 고역 변동 비 q_c 가 0.5~2. 같은 조명을 받으면 상대 변동이 비슷하다. 배경이 훨씬 크게 변하면(움직이는 물체) 나누지 않는다.
- 배경 밝기(피부 가중을 되돌린 값) ≥ 25, 배경 면적 ≥ 3 %. 패치 51 과 같은 기준이다.

## 5. 판정 규칙 (결과 전 확정, `scripts/bgref_judge.py`)
판정은 1차 셀과 2차 셀에 대해 각각 아래 가족으로 따로 한다(셀마다 Holm). 1차 셀이 주 결론이다.
- **가족 M (기전, Holm 2):** 지연 보정 r. M1 새 분리 시험의 전역 플리커 근접 12클립, M2 기존 전역 플리커 12클립(STRESS_INBAND6·NEAR6·TEST_C3). 클립별 5시드 평균의 쌍대 차이, 정확 부호 뒤집기 순열(양측). 지지: Δ > 0, Holm p < .05.
- **음성 대조(서술):** 피부 국소 플리커 근접 12클립. 배경에 보이지 않는 잡음이라 변화가 없어야 한다. 크게 오르면 M 의 이득이 조명 제거가 아닌 다른 효과라는 신호로 읽는다.
- **가족 P (실제 정확도, Holm 5):** VIPL-HR 전체, MMPD 7~33 전체, 풀 저심박, 풀 고심박, MR-NIRP 소동작. 지지: Δ < 0, Holm p < .05.
- **가드:** VIPL <60, VIPL ≥120, MMPD <110, MMPD ≥110, DLCN, RTNI, PURE. Δ > +0.3 bpm 이고 보정 없는 p < .05 면 위반이다.
- **해석:** M 지지는 입력 단계 비교로 같은 주파수의 전역 조명 잡음을 가른다는 뜻이다(합성). P 지지와 가드 유지는 실제 정확도로 이어진다는 뜻이다. 아무것도 지지되지 않으면 '측정되지 않음', 반대 방향 유의는 '역효과'로 쓴다.
- **결과를 쓰는 방법:** P 지지와 가드 유지면 최종 설정 교체 후보로 사용자에게 올린다(자동 교체 안 함). M 만 지지면 합성 영상 수준의 기전 근거로만 쓰고, 원고 반영은 사용자가 정한다.
- **사전 기록 주의:** 기준 셀은 체인 124 에서 이미 학습·평가했고 그 결과를 이미 봤다. 게이트 기준값은 §2.2 의 입력 통계를 보기 전에 정했고, 본 뒤 바꾸지 않았다. 풀은 체인 124 와 같다(합성 클립 48개 추가된 풀). 실제 시험 영상은 이전과 같다.

같은 주파수 전역 플리커에서 출력이 2배 심박으로 무너지던 실패는 대부분 사라졌다. 평가 때만 적용해도 같다. 그러나 잡음이 먼 클립과 주기 움직임 클립에서는 판독이 떨어졌고, 지연 보정 r 은 거의 모든 합성 세트에서 낮아졌다(예: 잡음이 먼 클립 0.70 → 0.47).

### 6.3 원인 진단: 생성기의 맥파 마스크가 배경으로 샌다(데이터 문제, 정직 보고)
게이트 형태(`scripts/bgref_gate_sets.py`, `results/bgref_gate_sets.json`)를 보면 OFFBAND6 는 모든 청크에서 세 채널을 다 나눴다(κ 0.92~0.96). 그러니 판독 하락은 일부 채널만 나눈 탓이 아니다. 생성기의 맥파 마스크(`amplitude_map.png`)를 보면, 시험 클립 얼굴 4개 중 3개에서 화면 왼쪽·오른쪽·위 12 % 띠의 60~99 % 가 맥파 마스크 안이다(sfhq04 만 16 %). 학습 클립에서도 정체성에 따라 1~91 % 다.
- 원인: `build_synth_dataset.py` 의 `stable_skin_mask` 가 YCrCb 피부색 범위로 피부를 잡아, 따뜻한 색 배경까지 맥파를 주입했다.
- 결과: 이 합성 클립들에서는 '배경'에도 맥파가 있다. 배경으로 나누면 얼굴의 맥파도 깎이므로, 합성 클립의 기전 시험은 교란된다. 실제 영상의 배경에는 맥파가 없으므로 실제 지표(가족 P)는 이 문제와 무관하다.
- 같은 이유로, 측면 띠 참조를 쓰는 투영 층도 이 합성 클립들에서는 맥파 성분을 함께 지웠을 수 있다. 63·64·65 의 합성 분리 진단 해석에 영향이 있을 수 있다(미검증).
- 이 문제는 이번 체인에서 처음 발견했다. 수정은 §7(탐색)에서 시험한다.

- 주기 머리 움직임 클립은 게이트가 일부 열리면서 판독이 조금 떨어진다(0.69 → 0.60, 4클립, 유의하지 않음). 결합 기준이 움직임에도 반응하는 한계다.
- 이 비교는 누출을 본 뒤 시험 클립을 고쳐 다시 잰 탐색이다. 실제 영상의 결론(§6.1: 실제 지표 지지 없음, 가드 유지)은 그대로다. 실제 데이터에서는 게이트가 3~7 % 청크에서만 열리고, 실제 오차는 같은 주파수의 전역 조명 잡음이 주원인이 아니다. RTNI(실제 + 통제 플리커, 8편)는 대부분 오차 0 이고 게이트 셀에서 몇 편이 한 칸(8.8~10.5 bpm) 달라졌다(유의하지 않음).

## 8. 데이터 문제: 합성 학습 클립의 약 절반에서 맥파가 배경에도 들어 있다 (정직 보고)
학습 풀의 생성 얼굴 클립에서 화면 가장자리 띠의 맥파 마스크 비율이 0.3 을 넘는 클립은 TRAIN20H_TW 10/20, TRAIN6HI_TW 3/6, TRAIN6LO_TW 3/6, TRAIN24DN 11/24, TRAIN24DN2 11/24, TRAIN48DR 23/48 이다. 정체성별 평균은 sfhq_01 0.79, sfhq_06 0.63, sfhq_05 0.26, sfhq_02 0.15, sfhq_03 0.01 이다. 원래 풀의 합성 80클립 중 38클립이 이에 해당한다.
- 영향(검증하지 않음): 합성 클립에서는 배경도 맥박 친다. 실제 영상과 다른 단서라, 64 §5 에서 합성 클립을 빼면 MMPD 가 좋아진 이유의 하나일 수 있다. 측면 띠를 참조로 쓰는 투영 층이 합성 클립에서 맥파 성분을 함께 지웠을 수 있어, 63·64·65 의 합성 분리 진단도 이 영향을 받았을 수 있다.
- 수정: `skin_mask_parser` 로 다시 생성하면 된다. 학습 풀을 고쳐 다시 학습하는 것은 하지 않았다(사용자 결정).
